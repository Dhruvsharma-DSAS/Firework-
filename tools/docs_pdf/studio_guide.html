Preparing your data for Data Studio

Data Studio puts your own fire points — field reports, a NASA FIRMS download, a list of burn sites — on the same 3D Earth as the satellite record. This guide shows exactly what the file should look like, which columns it needs, what happens to it, and the short documentation sheet that should travel with it.

PageYour data → Data Studio (firework-chronos.vercel.app/studio)
Accepts.csv, .tsv or .txt · up to 25 MB · the first 20,000 data rows are read
PrivacyStays in your browser · the file is never uploaded to a server
You get backYour points on the globe, a validation report and a cleaned CSV with standard column names

What a file looks like

One row per fire point, one column per property

The first row is the header: one short name per column. Every following row is one observation — one place where fire was seen, with its date and time. The example below is the first rows of the sample file you can download from the Data Studio page (NASA FIRMS, VIIRS S-NPP archive, Punjab and Haryana, October 2013).

The columns

Two are required, the rest make the result richer

Column names do not have to match exactly: the studio recognises the common alternatives in the last column and lets you map any other name by hand in step 4.

ColumnNeedMeaning and formatExampleAlso recognised
latitudeRequiredDecimal degrees, WGS84, north positive, −90 to 9030.11401lat, y
longitudeRequiredDecimal degrees, WGS84, east positive, −180 to 18075.33974lon, lng, long, x
acq_dateRecommendedDate of the observation, YYYY-MM-DD, in UTC2013-10-17date, datetime
acq_timeOptionalTime in UTC as HHMM; gives local solar time = UTC + longitude ÷ 150707time, utc
frpOptionalFire radiative power in megawatts; sets the spike height on the globe4.28power
confidenceOptionalKept as written: VIIRS l / n / h, MODIS 0–100 — never turned into a probabilityn—
satellite, instrument, daynightOptionalKept for your own reference; not needed for the globeN, VIIRS, D—

Format rules

Five rules that prevent almost every error

RuleDoAvoid
SeparatorComma, semicolon or tab — detected from the header rowMixing separators in one file
DecimalsA dot: 30.114A comma: 30,114 (read as two columns)
CoordinatesDecimal degrees: 30.114, 75.340Degrees-minutes-seconds: 30°06′50″N
TimeUTC, as on FIRMS downloadsLocal clock time without saying so
Empty valuesLeave the cell emptyWriting 0 or −999 for “unknown”

A good file

  • One header row, then one point per row
  • Latitude and longitude in decimal degrees
  • Dates as YYYY-MM-DD, times in UTC
  • Unknown values left empty
  • Saved as UTF-8 .csv

Common mistakes

  • Latitude and longitude swapped (points land in the ocean)
  • Extra title lines above the header
  • Merged cells or totals copied from a spreadsheet
  • Local time used as UTC (wrong solar hour)
  • “0” used for missing fire power

What happens to the file

Ten steps, from upload to export

01
Upload. Drop or choose the file. It is read by your browser; nothing is sent to a server.
Live
02
Inspect. The header and first rows are shown exactly as read, so a wrong separator or shifted columns are visible at once.
Live
03
Validate. Every row is checked: coordinates must be numbers inside −90…90 and −180…180. Bad and empty rows are counted, never silently fixed.
Live
04
Map columns. Say which column is latitude, longitude, date, time and FRP. FIRMS names are recognised automatically.
Live
05
Parameters. Choose the match radius and time window for comparing your points with NASA FIRMS.
Next
06
Preview. Valid points are drawn on the globe in violet, so you see whether they land where you expect.
Live
07
Run. Send the cleaned points to the backend comparison job.
Next
08
Formulas. Apply the same cell-day, local-solar-time and exchange-rate formulas (F01–F07) used for the fire record.
Next
09
Compare. Match each point to MODIS and VIIRS pixels and report hits, misses and distance.
Next
10
Export. Download the cleaned, validated points as a tidy CSV with standard column names.

What you get back

The cleaned CSV

Only rows that passed validation are exported, with the same column names whatever your file used. Local solar hour is computed for you when a time was given; FRP stays empty when it was missing.

latitude,longitude,acq_date,acq_time_utc,local_solar_hour,frp_mw
30.11401,75.33974,2013-10-17,0707,12.14,4.28
30.74212,76.5129,2013-10-17,0707,12.22,3.43

Local solar hour = 07:07 UTC = 7.12 h; 7.12 + 75.34° ÷ 15 = 12.14 h (formula F01).

Documentation to write

A one-page dataset sheet travels with every file

A table of points is only useful if the reader knows where it came from. Before you share a file — or compare it with satellites — fill in a short dataset sheet. It answers the questions a scientist, an officer or a journalist will ask first, and it is how FIREWORK keeps every number honest. Save it as README.txt next to your CSV, or as the first page of your report.

FieldWhy it matters
Title and ownerWho is responsible for the data and whom to contact
Source and methodSatellite download, field survey, phone reports … each has different errors
Period and areaSo readers do not compare it with the wrong months or places
Coordinates and timeDatum (WGS84) and time zone (UTC or local) — the two most common hidden errors
Columns and unitsWhat every column means, in which unit
Known limitsWhat the data cannot show: missed fires, duplicates, approximate places
Status labelOne of FIREWORK’s five labels: official, source-derived, tested locally, simulated, proposed
LicenceWho may reuse it and how to credit it
